Backwards Design Exercise

What Memory Architecture Do These Benchmarks Demand?

Taking the adversarial memory benchmarks — contested claims, citation cascades, episode reconstruction, causal attribution — and reverse-engineering the memory system that would need to exist to answer their queries correctly.

The Dataset in Miniature

Experiment 05 simulates a tidal-energy turbine investigation. Turbine T-4 keeps tripping. Over five months, the investigation team forms hypotheses, finds evidence, changes its mind, prematurely closes the case, reopens it, and ultimately arrives at a different answer than where it started. Along the way:

25 distinct claims tracked independently, each with its own evidence base, belief trajectory, and resolution status. Some are confirmed true, some confirmed false, some permanently unresolvable, and some reopened after premature closure.

Here's what makes this dataset adversarial. The biofouling claim (C03) appears in 11 supporting documents — status reports, chat messages, weekly digests — but every single one traces back to one misread log entry. Two independent observations (a dive inspection and an independent accelerometer) later disprove it. A naive memory system that counts mentions would say biofouling is well-supported. The correct answer is that it's false.

C03 "Biofouling on VIB-4A is causing T-4 trips" disproven
C05 "Main shaft bearing is worn and degrading" confirmed
C01 "March trips caused by PCM ground fault" underdetermined
C06 "Harmonic resonance is the root cause" unsupported
C23 "RCA resolved → reopened → resolved differently" corrected

And here's the belief trajectory for just one claim — biofouling (C03). A memory system needs to answer questions about any point on this timeline, not just the final state:

probable
still probable
disproven
Mar 22 Apr 14 — 10 restatements, 0 new evidence May 15

Fourteen Primitives the Datasets Demand

Working backwards from the queries the benchmarks expect a system to answer, these are the structural primitives without which correctness is impossible. Not nice-to-haves — each one has a specific query that breaks without it.

The first nine are established — derived from actual generated datasets (Experiments 01–09) with concrete memories, claims, and ground-truth queries. The last five are projected pending datasets — derived from the experiment descriptions for Experiments 10–20. Their general shape is clear; their precise structure will sharpen when the datasets are generated.

1. Triple-Timestamp Records

Every memory must carry three independent timestamps: event_time (when the thing happened), observation_time (when someone noticed or recorded it), and ingestion_time (when the system learned about it). These three can diverge by months.

// Exp 05 example: teardown finding { "event_time": "2027-04-12", // bearing replaced this day "observation_time": "2027-06-20", // teardown reveals calibration drift "ingestion_time": "2027-06-20", // entered into system same day }

Without this: the system can't answer "what was known on April 14?" vs "what had actually happened by April 14?" — these are different questions with different answers.

2. Claim-Level Granularity

The atomic unit of tracking must be the claim, not the document. A single memory record can contain multiple claims with different truth values. Exp 05's MESB final report simultaneously confirms bearing wear (true), leaves the March trips underdetermined (unresolved), and closes the biofouling theory (false).

Claim { "claim_id": string, "fact_id": string, // groups related claims "claim_text": string, "objective_status": enum, // oracle only "resolution_status": enum, // what the system can derive "supporting_evidence": [evidence_id], "contradicting_evidence": [evidence_id], "independent_roots": int, // NOT total mentions "memory_ids": [memory_id], "belief_states": timeline_map, }

3. Epistemic State Timeline

For each claim, the system must track what different actors believed at different times. This isn't the same as the claim's objective truth — it's about beliefs, and beliefs can be wrong, partial, or held with different confidence by different groups.

"belief_states": { "2027-03-26": { "investigation_team": "probable", "kelvinbridge_team": "probable" }, "2027-06-03": { "investigation_team": "unlikely", "kelvinbridge_team": "unlikely" }, "2027-07-01": { "investigation_team": "disproven", "kelvinbridge_team": "disproven" } }

Note that investigation_team and kelvinbridge_team can hold different beliefs at the same time. And the belief "probable" does not mean the claim is true — C03 was rated "probable" for weeks while being objectively false.

4. Evidence Independence Tracking

This is the hardest primitive and the one most memory systems lack entirely. The system must distinguish between independent evidence roots (separate observations by separate instruments/people) and derivative restatements (copies, summaries, and citations of the same root).

5. Derivation Graph

Every memory must declare its provenance: derived_from (which memories this one draws on), supersedes (what it replaces), and contradicts (what it disputes). This forms a directed graph that the system must be able to traverse in both directions.

MemoryRecord { "derived_from": [memory_id], // provenance edges "supersedes": [memory_id], // temporal replacement "contradicts": [memory_id], // explicit disagreement }

Exp 06 takes this further with full provenance graph nodes, node types (evidence_root, primary_observation, interpretation, derived_summary, transformed_claim, copied_claim, etc.), and cycle detection. But even Exp 05 requires the basic traversal: "trace this claim back to its original evidence."

6. Multi-Resolution Status

The resolution status vocabulary must include states that most systems collapse into "unknown." Exp 05 requires at minimum:

CONFIRMED Evidence converges, claim is true (bearing wear, C05)
DISPROVEN Independent evidence refutes the claim (biofouling, C03)
UNDETERMINED Evidence exists both ways, no decisive test — may never resolve (March cause, C01)
REOPENED Was resolved, new evidence invalidated the resolution (RCA, C23)
SCOPE RECONCILED Apparent contradiction resolved by recognizing different scopes (C12/C13)

"Underdetermined" and "unresolved" are different. Unresolved means more evidence might settle it. Underdetermined means the evidence that exists is fundamentally insufficient — the story is designed so that no future discovery can resolve C01 for the March episode specifically.

7. Scope Qualifiers

Claims must carry structured scope metadata — what facility, instrument, time period, team, authority level they apply to. Without this, the system can't distinguish two claims that look contradictory but are scoped to different questions.

C12 (Park, electrical)

"No electrical fault occurred in the PCM at the moment of the June 2 trip."

Scope: whether a fault condition existed. True.

C13 (Costa, systems)

"The electrical protection system caused the June 2 shutdown."

Scope: what mechanism triggered the trip. Also true.

Both are confirmed true. A system without scope qualifiers would flag them as contradictory.

8. Episode Model

Experiment 08 introduces a requirement the Exp 05 architecture doesn't have at all: grouping scattered traces — commits, chat messages, CI runs, issue comments — into coherent episodes with defined boundaries, goals, participants, and inter-episode relationships.

An episode isn't a document or a time window. It's a goal-directed arc: "the team investigated the scheduler lease-expiry bug from January 8 to January 12." Traces from different systems (git, chat, CI, JIRA) belong to the same episode even when they're interleaved with unrelated work.

Episode { episode_id: string, label: string, type: enum, // incident_investigation | maintenance | feature // | migration | performance | security | planning goals: [string], start: datetime, end: datetime, participants: [actor_id], entities: [string], // systems, components involved memory_ids: [memory_id], boundary_confidence: enum, // high | medium | low }

The critical part is the relationship ontology between episodes. Two episodes that involve the same system aren't the same episode. Two episodes that happen months apart might be:

SIMILAR_TO Same type of problem, different root cause or trigger (EP04/EP05: both touch leases, but distinct goals)
OVERLAPS Concurrent in time, sharing resources or attention (EP02 and EP01: same week, different problems)
TRIGGERS One episode's outcome directly starts another (EP10 triggers EP11: discovery causes a response)
FOLLOWED_BY Sequential continuation of a broader arc (EP06 followed by EP10: pause then resumption)
CONTRIBUTES_CONTEXT_TO Earlier work provides knowledge used later (EP06 contributes context to EP11)

Exp 08's adversarial traps test six invariants that a naive system violates:

Temporal proximity ≠ same episode

EP01 and EP02 overlap in time but are completely unrelated. A time-window heuristic merges them.

Temporal separation ≠ different episode

EP06 pauses for months then resumes with the same goal, participants, and context. A timeout heuristic splits it.

Shared project ≠ same episode

EP04 and EP05 live in the same issue tracker and touch the same component. They have different goals.

Lexical similarity ≠ membership

EP03 and EP07 both involve auth token failures and use similar vocabulary. They're months apart with different causes.

Consequences ≠ members

An episode's consequences (a post-incident review, a triggered migration) are related episodes, not part of the original.

Missing evidence → ambiguity, not splitting

Removing one connective trace should degrade from confident membership to uncertain, not trigger an automatic split.

9. Causal Graph

Experiment 09 demands what may be the hardest primitive: typed causal relations with the discipline to resist post hoc reasoning, correlation-as-causation, and narrative pressure.

The causal relation vocabulary isn't binary (causes/doesn't). Exp 09 defines a spectrum:

CAUSES Mechanistically established direct cause (bus resistance → retries → lag)
CONTRIBUTES_TO Necessary but not sufficient alone (thermal load + firmware race together cause resets)
TRIGGERS Proximate initiator, not root cause (cert renewal triggers restart, but dependency cycle is the root cause)
ROOT_CAUSE_OF Distal structural cause (dependency cycle is root cause of stall; cert renewal merely triggers it)
PRECEDES Temporal sequence without causation (software deploy precedes lag but doesn't cause it)
CORRELATES_WITH Co-occurrence driven by a common cause (cooling demand correlates with sensor drift; both caused by ambient heat)
HYPOTHESIZED Candidate explanation with competing alternatives (two hypotheses for intermittent brownouts, neither confirmed)
PREVENTS Counterfactual: this mechanism stopped an outcome from happening (overcurrent protection prevents actuator damage)
CausalClaim { causal_claim_id: string, case_id: string, cause: string, // entity or compound (A+B for joint causes) effect: string, relation: enum, // CAUSES | CONTRIBUTES_TO | TRIGGERS // | ROOT_CAUSE_OF | CORRELATES_WITH | PRECEDES // | HYPOTHESIZED_CAUSE_OF | PREVENTS | SYMPTOM_OF status: enum, // established | unresolved | noncausal_sequence // | association_only confidence_class: enum, // high | medium | low evidence_ids: [memory_id], } CausalGraph { case_id: string, edges: [ { source: string, relation: enum, target: string } ], }

Exp 09's traps test specific causal reasoning failures:

Post hoc blame

A software deployment preceded the lag, so it "caused" it. But closer timing doesn't increase causal certainty when the mechanism is absent.

Traps: T09_01, T09_03

Correlation ≠ causation

Cooling demand and sensor drift co-occur. More co-occurrences shouldn't increase a direct causal claim when both are driven by ambient heat.

Traps: T09_02, T09_05

Trigger vs root cause

The cert renewal triggered the restart, but the dependency cycle is the root cause. An authoritative statement blaming the cert shouldn't change this.

Traps: T09_08, T09_11

Joint causes & confounded intervention

Two factors together cause resets; neither alone is sufficient. A fix that changes both simultaneously doesn't tell you which mattered.

Traps: T09_04, T09_10

Feedback loops

Network degradation causes retries; retries worsen degradation. The system must represent bidirectional causation without collapsing to "they cause each other."

Trap: T09_06

Retrospective reinterpretation

A later confident reinterpretation shouldn't rewrite the historical evidence state. What was uncertain then stays uncertain then.

Trap: T09_09
Projected Primitives — Pending Dataset Generation

10. Tombstone & Retraction Model projected

Experiment 11 (Forgetting / Retraction / Deletion Semantics) asks a question most memory systems don't have an answer for: what does it actually mean to forget something? The current architecture can track claims that change status, but it has no mechanism for memories that should no longer exist.

The problem is that "delete" isn't one operation. It's at least four:

SUPERSEDED No longer current, but historically valid. "We used to use AURORA" — true then, not true now.
RETRACTED Was wrong when stated. The source explicitly retracts the claim. Historical queries should note the retraction.
EXPUNGED Must not be retrievable. Privacy/legal deletion. System must not surface it, not even as "there used to be something here."
SOURCE LOST The upstream source was deleted. Derived memories exist but can't be re-verified. A different epistemic status than retraction.

The hardest part is the derivation-graph orphan problem: when a source memory is deleted, what happens to memories derived from it? A summary built from five sources, one of which is expunged, can't simply be deleted (it contains information from four legitimate sources) but also can't remain unchanged (it contains information that must not be surfaced). This is where the actual dataset will matter most — the edge cases around partial deletion of derivation chains are where the architectural shape will sharpen.

Tombstone { memory_id: string, // what was deleted deletion_type: enum, // superseded | retracted | expunged | source_lost deleted_at: datetime, reason: string?, historical_access: enum, // allowed | noted_as_retracted | forbidden orphaned_derivations: [memory_id], // derived memories now missing a source }

11. Namespace & Visibility Layer projected

Experiment 12 (Privacy Boundaries / Namespace Isolation) tests whether memory from one context can leak into another. This is fundamentally an access-control layer over the entire memory model.

The architectural issue isn't just "tag each memory with a tenant ID." It's that the system's derived structures — claims, summaries, belief timelines, episodes — can be built from memories spanning multiple visibility scopes. A summary built from Alice's private notes and Bob's private notes could leak information from both into a shared context where neither intended it.

VisibilityScope { namespace: string, // tenant, project, or user boundary access_level: enum, // private | team | project | org | public granted_to: [principal_id], revocable: bool, // can access be withdrawn after grant? }

Key questions the dataset will need to answer: What happens when access is revoked after a derived memory was built from the now-restricted source? Does the derived memory inherit the strictest scope of its inputs? What about cross-tenant alias collisions — two tenants both have an entity called "Project Alpha"?

12. Compression Fidelity Tracking projected

Experiment 13 (Consolidation / Summarization Drift) tests what happens when raw memories are compressed into summaries, and those summaries are compressed again. Each pass can lose qualifiers ("probably" → "likely" → stated as fact), drop uncertainty, flatten time, and collapse distinct entities.

The current derivation graph knows that a memory was derived from another. What it doesn't track is what was lost in the derivation. A summary that drops "in Q1 only" from a scoped claim is a semantic corruption, not just a compression.

CompressionRecord { summary_id: memory_id, source_ids: [memory_id], generation: int, // 1 = summary of originals, 2 = summary of summaries, ... preserved_properties: [string], // which semantic properties survived lost_properties: [string], // what was dropped or weakened qualifier_drift: [QualifierDelta],// "probably" → "is", "Q1 only" → dropped }

The adversarial structure: a chain of 4–5 summarization generations where each step is locally reasonable but the final summary contradicts the original source. Controlled experiments where exactly one qualifier is dropped per generation, so you can measure where the semantic break occurs.

13. Metadata Confidence Model projected

Experiment 15 (Contradictory Metadata / Poisoned Metadata) breaks an assumption the entire current schema relies on: that structured metadata fields are trustworthy. What happens when a memory's event_time is wrong? When the source_type says "sensor_log" but the text is clearly a meeting note? When the entity ID points to the wrong entity?

The current triple-timestamp model assumes timestamps are correct. But if the system ingests a memory with a wrong event_time, every temporal query that touches it returns wrong results — and the system has no way to detect the corruption because timestamps are trusted infrastructure, not claims subject to evidence.

MetadataConfidence { field: string, // which metadata field stated_value: any, // what the metadata says confidence: enum, // verified | inferred | stated | uncertain | contradicted text_agrees: bool?, // does the text content agree with this field? corroborating_ids: [memory_id], // other memories that support this value }

The core invariant: when metadata and text disagree, the system must flag the disagreement rather than silently trusting either one. The dataset needs both directions: metadata correct / text misleading, and text correct / metadata wrong, with controls where both agree.

14. Negation & Counterfactual Model projected

Experiment 18 (Counterfactual / Negative Evidence) tests whether the system can remember things that didn't happen without later converting them into things that did. "The team considered switching to Kestrel but decided against it" is a meaningful memory that a retrieval system easily corrupts into "the team switched to Kestrel."

The current schema has no way to represent negation as a first-class structure. A memory's predicate field can say "rejected" but there's no structural guarantee that a retrieval query for "Kestrel adoption" won't surface the rejection memory as evidence for adoption.

CounterfactualRecord { memory_id: string, assertion_polarity: enum, // positive | negative | counterfactual | abandoned considered_action: string?, // what was proposed/predicted/planned actual_outcome: enum, // enacted | rejected | prevented | never_occurred prevention_cause: string?, // what stopped it, if anything }

The adversarial trick: abandoned plans, disproven hypotheses, and failed predictions are all true memories about non-events. The system must retrieve them when asked "what was considered?" without surfacing them when asked "what happened?" This is structurally different from a false claim — the memory itself is true, it's the thing it describes that didn't happen.

Each operation maps to a specific query category in the benchmark. The table shows the operation, what it needs from the data model, and the Exp 05 query that tests it.

Historical belief retrieval Epistemic timeline "As of 2027-04-05, how confident was the team that the March trips had an electrical cause?" (e05q_004)
Independence counting Derivation graph, root tracing "Is biofouling supported by multiple independent observations, or by repeated restatement?" (e05q_006)
Forced-choice resistance Multi-resolution status, abstention model "Were the March trips caused by Hypothesis E or Hypothesis M?" (e05q_001) — correct answer: neither can be chosen

What Breaks Without Each Primitive

The backwards-design test: remove each primitive and identify the specific failure.

Without triple timestamps

Can't distinguish "what happened" from "what was known." The teardown finding (event April, observation June) gets placed at the wrong point in the investigation timeline.

Breaks: e05q_004, e05q_009, e05q_010

Without claim-level tracking

The MESB final report becomes a single "true" or "false" record, when it actually confirms one claim, leaves another underdetermined, and closes a third as false.

Breaks: e05q_001, e05q_002, e05q_007

Without epistemic timeline

Can't answer "what did the team believe on date X?" independently from "what is true?" The April 14 query returns "disproven" instead of the historically correct "probable."

Breaks: e05q_004, e05q_010

Without independence tracking

11 mentions of biofouling outweigh 2 disconfirmations. The system endorses a false claim because it mistakes repetition for corroboration.

Breaks: e05q_006, e05q_009

Without derivation graph

Can't trace the biofouling claim to its single misread-log root. Can't reconstruct how the harmonic resonance claim escalated from whiteboard speculation to "official working theory" without new evidence.

Breaks: e05q_006, e05q_008

Without multi-resolution status

The March cause (C01) gets forced into "true" or "false" when the correct answer is "underdetermined." The RCA (C23) can't represent "resolved then reopened then resolved differently."

Breaks: e05q_001, e05q_002, e05q_003

Without scope qualifiers

Park's and Costa's June statements get flagged as contradictory when both are correct about different things. The S2 generator-only exception (from Exp 01) gets overgeneralized to the whole site.

Breaks: scope disagreement queries

Without abstention model

Forced-choice query e05q_001 gets a confident wrong answer instead of the correct "evidence doesn't justify choosing either." The system hallucinates certainty.

Breaks: e05q_001, e05q_003

Without episode model

Concurrent but unrelated work gets merged into one blob (EP01+EP02). A long pause in an ongoing investigation causes a false split (EP06). Lexically similar incidents get conflated (EP03/EP07).

Breaks: T08_01 through T08_10

Without causal graph

Temporal proximity becomes causal attribution: the software deployment "caused" the lag because it happened first. Correlated effects get linked as cause→effect. The trigger gets blamed instead of the root cause.

Breaks: T09_01 through T09_11

Without tombstone model projected

A retracted memory's claims persist in derived summaries. An expunged memory still surfaces through memories that quote it. "Deletion" means invisible but not gone.

Breaks: Exp 11 deletion compliance

Without namespace layer projected

A shared summary built from private sources leaks information across tenant boundaries. "Project Alpha" in Tenant A collides with "Project Alpha" in Tenant B.

Breaks: Exp 12 namespace isolation

Without compression tracking projected

A fourth-generation summary states as fact what the original qualified with "probably, in Q1 only." No mechanism detects the qualifier drift.

Breaks: Exp 13 fidelity audit

Without metadata confidence projected

A memory with a wrong event_time silently corrupts every temporal query it participates in. The system can't flag that the text says "August" while the timestamp says "March."

Breaks: Exp 15 metadata cross-check

Without negation model projected

"The team considered switching to Kestrel but decided against it" gets retrieved as evidence for a Kestrel adoption. Abandoned plans, rejected proposals, and disproven hypotheses become false positives.

Breaks: Exp 18 counterfactual retrieval

Cross-Experiment Coverage

Does this nine-primitive architecture handle all the experiments? Here's the breakdown.

Exp 01 (Temporal Traps) — covered

Triple timestamps, supersession chains, scope qualifiers, and alias handling are all in the base model. The site rename (Echo Camp → Nadir Station) needs an aliases field on memory records, already present in the Exp 01 schema.

Exp 02 (False Consensus) — covered

Citation cascades, exact/semantic duplication, and rumor propagation are handled by the derivation graph and independence tracking. The "retrieval self-amplification" trap (where search results reinforce the majority claim) is an evaluation-time concern, not a schema concern.

Exp 06 (Roots, Echoes, Lineage) — needs extension

Requires typed provenance nodes (evidence_root, primary_observation, interpretation, derived_summary, transformed_claim, copied_claim, quoted_claim, model_generated, reingested) and cycle detection on the derivation graph. Also needs tombstoned source handling — a source that existed and was cited but is no longer retrievable.

Exp 07 (Shape of What Is Not Known) — needs extension

Requires a missingness model: structured representation of why something is unknown (never_recorded, observation_gap, inaccessible_source, partial_observation, misleading_premise, lost_evidence). Also needs premise validation — the ability to reject a question's framing rather than answering it ("When did the second generator fire?" → "There was no second generator fire").

Exp 08 (Episode Reconstruction) — covered by Primitive 8

The episode model (boundaries, goals, participants, relationship ontology) is purpose-built for this experiment. The five relationship types (SIMILAR_TO, OVERLAPS, TRIGGERS, FOLLOWED_BY, CONTRIBUTES_CONTEXT_TO) and the six invariants it tests are directly addressable with this structure. The 170 background distractors and 10 perturbation variants test whether the episode model is robust against lexical, temporal, and artifact-level cues.

Exp 09 (Causal Attribution) — covered by Primitive 9

The causal graph (typed relations, status, confidence class) handles the 10 causal cases and 23 causal claims. The key insight is the relation vocabulary — distinguishing CAUSES from TRIGGERS from PRECEDES from CORRELATES_WITH is exactly what the 11 adversarial traps test. Joint causes (A+B) need compound entity representation. The status field (established, unresolved, noncausal_sequence, association_only) prevents the system from collapsing "temporal precedence" into "causation."

Experiments 10–20 — Projected Coverage

Exp 10 (Ingestion Order / Late Arrival) — covered by existing primitives

Triple timestamps already separate event_time from ingestion_time. The test is whether the system's operations are order-independent — do you get the same derived state regardless of whether memories arrive chronologically, shuffled, or with late arrivals? This is an operational invariant on the existing data model, not a new primitive. Exp 05 already ships three ingestion orderings (chronological, shuffled, late-arrival) as a partial test.

Exp 11 (Forgetting / Retraction / Deletion) — needs Primitive 10 projected

Requires the tombstone & retraction model. The current architecture has no mechanism for memories that should cease to exist, especially the derivation-graph orphan problem: derived memories whose sources have been deleted, retracted, or expunged. The four deletion types (superseded, retracted, expunged, source_lost) each have different semantics for historical queries, derivation chains, and claim status. This is the experiment most likely to reveal architectural surprises.

Exp 12 (Privacy Boundaries / Namespace Isolation) — needs Primitive 11 projected

Requires the namespace & visibility layer. Every layer in the current architecture — claims, belief timelines, derivation graphs, episodes, causal graphs — operates without access control. The experiment tests whether derived structures leak information across boundaries, particularly when a summary or claim was built from sources spanning multiple scopes.

Exp 13 (Consolidation / Summarization Drift) — needs Primitive 12 projected

Requires compression fidelity tracking. The derivation graph already records that one memory derives from another, but it doesn't track what was lost in the derivation. Multi-generation summarization chains where each step is locally reasonable but the final summary contradicts the original are the core adversarial structure.

Exp 14 (Semantic Near-Miss / Distractor Resistance) — retrieval-layer concern

Primarily tests the retrieval layer, not the data model. Whether a system over-relies on embedding similarity vs. evidence quality is important but doesn't demand a new schema primitive. The existing scope qualifiers and triple timestamps provide the structured fields a retrieval system would need to distinguish lexically similar but semantically different memories.

Exp 15 (Contradictory Metadata / Poisoned Metadata) — needs Primitive 13 projected

Requires a metadata confidence model. The current schema treats structured fields (timestamps, source_type, entity IDs) as trusted infrastructure. This experiment tests what happens when they're wrong, and whether the system can detect disagreement between metadata and text content.

Exp 16 (Multi-hop / Long-range Dependency) — covered by existing primitives

Tests traversal depth on the derivation graph, claim graph, and temporal joins. The primitives are already in the schema; the test is whether the system can reconstruct facts that span multiple memories, entities, and time periods without hallucinating the missing links. No new primitive needed, but the existing graph structures must support efficient multi-hop queries.

Exp 17 (Belief State vs Objective State) — covered by Primitive 3

The epistemic timeline (Primitive 3) was built for exactly this. The experiment pushes it deeper into individual vs. team vs. organizational vs. publicly-reported belief layers — the current schema supports this via the actor key in belief_states, but the dataset will test whether the system can maintain five or more parallel belief tracks without collapsing them.

Exp 18 (Counterfactual / Negative Evidence) — needs Primitive 14 projected

Requires a negation & counterfactual model. Abandoned plans, disproven hypotheses, and prevented outcomes are true memories about non-events. The system must retrieve them when asked "what was considered?" without surfacing them when asked "what happened?" — a structural distinction the current schema doesn't make.

Exp 19 (Repeated Exposure / Confidence Inflation) — covered by Primitives 4 & 5

Tests independence tracking and derivation graph at the system-operation level. The adversarial structure is retrieve-and-resave loops where the system's own outputs are reingested as source memories. The derivation graph should tag these as reingested or model_generated (Exp 06's provenance node types), and independence counting should refuse to count them as new roots.

Exp 20 (Benchmark Crossover / Compound Failure) — meta-experiment

Not a primitive test but a composition test. Designed to run after the individual families have been characterized. Tests whether mechanisms that handle each adversarial family individually fail under composition — e.g., temporal traps + false consensus, or privacy namespaces + alias collisions. The architecture should be designed so primitives compose without interference, but that's exactly what this experiment verifies.

The Core Insight

Most memory systems are retrieval systems with a truth assumption: store text, retrieve text, and assume retrieved text is true. These benchmarks show that this assumption is the failure mode, not a simplification.

The architecture these datasets demand is fundamentally different: it's a system that stores claims with provenance and confidence trajectories, not text with timestamps. It can say "I don't know," "I can't know," "I used to think X but now think Y," and "these two things look contradictory but they're answering different questions." It groups scattered traces into goal-directed episodes without confusing proximity for membership. It attributes causation through mechanism, not through temporal coincidence or narrative authority.

Retrieval is necessary but not sufficient. The hard problems are all post-retrieval: independence counting, scope comparison, belief-state reconstruction, episode boundary detection, causal reasoning, and the discipline to abstain when the evidence doesn't support a conclusion.

The projected primitives push the architecture further: a memory system must also know how to forget (without orphaning derivatives), how to isolate (without leaking through shared summaries), how to compress (without silently dropping qualifiers), how to doubt its own metadata, and how to remember things that didn't happen as structurally distinct from things that did. The nine established primitives give the system a truthful memory. The five projected primitives give it a responsible one.

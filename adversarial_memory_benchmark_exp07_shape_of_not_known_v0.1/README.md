# Adversarial Memory Benchmark — Experiment 07: The Shape of What Is Not Known (v0.1)

Parser-ready synthetic benchmark bundle, packaged to match the Experiments
03/04 bundle convention.

Central research question: **can a memory system say "I don't know" for the
right reasons, and avoid saying it when negative evidence actually supports
an answer?**

## Scale

- Experiment 07: **358 memories**, **80 queries**, **51 missingness-map
  claim entries** (+2 direct control anchors)

This sits inside the spec's requested 200-1,000 range and comfortably inside
its preferred 300-650 range, without padding: every one of the ~290 narrative
filler memories is a distinct, non-repeating routine-life record (weather
rounds, meal duty, roll calls, maintenance rounds, handover notes, personal
chat), and every one of the 53 trap/control claims is backed by hand-authored,
claim-specific evidence rather than templated boilerplate. All 13 required
adversarial subfamilies (§07.1-07.13) and all 7 control conditions (§4 A-G)
are represented, each with 2 or more claims. All 8 controlled-perturbation
dimensions (§8 P07-A..H) are grounded as concrete minimal pairs inside this
single corpus (see `perturbations/perturbation_plan.json`), rather than
described only in the abstract.

## Hidden fields

`memories.jsonl` contains an `_oracle` object for benchmark development. A
production harness should be able to strip `_oracle`, `subject_entity_id`,
`truth_role`, and/or normalized `scope` fields depending on the condition
being tested. `_oracle.claim_id` links a memory back to its
`missingness_map.json` proposition; `_oracle.coverage_role` distinguishes
load-bearing evidence (`trap_anchor`, `supporting`, `control_anchor`) from
ambient narrative texture (`narrative_filler`).

## Important semantic distinctions

- **A null scope value is not automatically "global."** As in Experiments
  03/04, the oracle files distinguish specified, unknown, and omitted scope.
- **"No matching memory" is not automatically "false."** Whether an absent
  record licenses a negative answer depends entirely on whether the relevant
  channel is exhaustive for that specific scope and window — see
  `story_bible.md`'s Observability Model and `missingness_map.json`'s
  `negative_inference_valid` field. Several claims are correctly represented
  by there being **no memory at all** for a given window (e.g. the pre-Day-63
  Tunnel Door); this is deliberate, not a generation gap.
- **Existence of a source is not existence of its content.** Several memories
  confirm that a document, email, or recording exists while its content
  remains permanently or historically inaccessible — see `missingness_type`
  values `inaccessible_source`, `lost_evidence`, and `document_never_existed`
  in `missingness_map.json`, which are deliberately distinct categories.

## Regenerating / validating this bundle

The corpus was generated by a small set of Python scripts (claim catalog →
memories/provenance/ingestion variants → queries/missingness map →
experimental map) rather than hand-typed JSON, to keep the story bible, the
experimental map, the memory corpus, and the query ground truth mutually
consistent. The generation scripts themselves are a scratch artifact of this
session and are not included in the shipped bundle (matching the Experiments
03/04 convention of shipping only the generated corpus, not its generator).

To validate this bundle:

```bash
# All files are valid JSON / JSONL:
python3 -c "
import json, glob
for path in glob.glob('experiment_07_the_shape_of_what_is_not_known/*.jsonl'):
    for line in open(path):
        json.loads(line)
for path in ['schema.json','manifest.json',
             'experiment_07_the_shape_of_what_is_not_known/truth_state.json',
             'experiment_07_the_shape_of_what_is_not_known/provenance.json',
             'experiment_07_the_shape_of_what_is_not_known/missingness_map.json',
             'experiment_07_the_shape_of_what_is_not_known/perturbations/perturbation_plan.json']:
    json.load(open(path))
print('all JSON/JSONL valid')
"

# memory_id / query_id uniqueness and required-field presence can be checked
# the same way against schema.json's required-field lists.

# Checksums:
python3 -c "
import json, hashlib
data = json.load(open('checksums.sha256.json'))
import os
for relpath, expected in data.items():
    with open(relpath, 'rb') as f:
        actual = hashlib.sha256(f.read()).hexdigest()
    assert actual == expected, f'MISMATCH: {relpath}'
print('all checksums match')
"
```
